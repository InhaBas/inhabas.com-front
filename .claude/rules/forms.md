# 폼 UX 규칙

사용자가 값을 입력하는 화면(가입, 게시글 작성, 내정보 수정 등)을 만들거나 고칠 때 따른다. 기준은 로그인·회원가입 개선에서 실제로 적용한 것이고, 구현 예시는 `src/pages/member/Signup.tsx`(1단계)와 `SignupQuestion.tsx`(2단계)다.

새 폼은 `src/components/common/form/`의 공용 부품으로 만든다. 라벨, 고정 높이 메시지 영역, `aria-invalid`·`aria-describedby` 연결, 포커스 링, 48px 높이, 16px 글자는 부품이 이미 지킨다. 부품으로 안 되는 경우만 아래 체크리스트를 직접 맞춘다.

## 폼 상태와 검증 규칙

- 폼 상태는 react-hook-form으로 관리한다. `mode: 'onTouched'`로 쓴다.
- 직접 입력하지 않는 값(모달에서 고른 전공, 세그먼트)은 `Controller`로 연결한다.
- 조건에 따라 필요 없는 칸은 렌더링하지 않는다. 등록되지 않은 칸은 검사도 하지 않는다.
- 규칙은 RHF 기본 규칙(필수, 길이, 정규식, `validate`)으로 쓴다. zod와 resolver는 아래 중 하나가 생기면 다시 검토한다.
  - 회원가입 밖의 폼(내정보 수정, 게시글 작성 등)을 RHF로 옮길 때
  - 같은 규칙을 서버 응답 확인에도 써야 할 때
- 서버가 거절하는 값의 규칙은 폼마다 하나의 규칙 모듈에 모으고, 규칙마다 근거가 된 백엔드 `파일:줄`과 커밋을 주석으로 단다. 예: `src/functions/signUpRules.ts`.

### 백엔드 규칙 동기화

규칙 모듈의 기준 커밋이 백엔드 main과 다를 때, 또는 서버가 프론트 검증을 통과한 값을 거절할 때 한다.

1. `backend-contract` 스킬로 백엔드 main을 받아, 규칙 모듈 주석의 파일마다 기준 커밋 이후 변경을 확인한다.
2. 바뀐 규칙은 값과 오류 문구를 고친다.
3. 모듈 머리 주석의 기준 커밋과 날짜, 규칙마다 단 `커밋 파일:줄`을 새 커밋 기준으로 모두 고친다. 규칙이 그대로여도 줄 번호가 밀렸으면 고친다.

모듈의 모든 주석이 같은 새 커밋을 가리키면 끝이다.

## 체크리스트

- **라벨**: 모든 칸 위에 항상 보이는 라벨을 둔다. placeholder에는 형식 예시만 쓴다(`12112233`). 라디오·세그먼트 묶음은 묶음 이름을 라벨로 연결한다.
- **오류 위치와 aria**: 오류는 해당 칸 바로 아래 고정 높이 영역에 문구와 아이콘으로 함께 표시한다. 칸에 `aria-invalid`를 달고 오류 문구를 `aria-describedby`로 연결한다. 글자 수처럼 칸을 설명하는 다른 내용도 같은 `aria-describedby`에 합친다(`FieldFrame`의 `aside`).
- **검증 시점**: 처음에는 칸을 벗어날 때와 제출할 때 검사하고, 한 번 오류가 난 칸은 입력할 때마다 다시 검사한다(`onTouched`). 제출에 실패하면 오류를 모두 표시하고 화면 순서로 첫 오류 칸에 포커스를 옮긴다. RHF는 등록 순서로 포커스하므로 `shouldFocusError: false`로 두고 `onInvalid`에서 화면 순서를 따라 `setFocus`한다.
- **서버 오류**: 칸을 특정할 수 있으면 칸 오류로, 없으면 폼 위 `FormBanner`로 알리고 입력값은 그대로 둔다. 화면이 서버 오류를 직접 다루는 방법은 `docs/frontend/TANSTACK-QUERY.md` 5.1을 따른다.
- **상태**: 제출 중에는 버튼을 `disabled`·`aria-busy`로 막고 스피너와 진행형 문구를 보여 준다. 진행형 문구는 버튼이 하는 일 그대로 쓰되, 같은 화면의 다른 진행 표시와 겹치지 않게 한다(1단계 "저장 중…", 임시저장이 있는 2단계 제출 "제출 중…"). 임시저장이 있으면 저장 안 됨·저장 중·저장됨(시각)·실패를 `role="status"`로 보여 준다.
- **입력 속성**: 브라우저가 채울 수 있는 칸에 `autoComplete`(`name`, `tel` 등)를 단다. 숫자만 받는 칸은 `inputMode="numeric"`을 쓴다. 형식이 정해진 값은 입력하는 대로 맞춰 준다(전화번호 하이픈).
- **터치·글자 크기**: 입력과 버튼은 높이 48px 이상(터치 영역 44px 이상), 입력 글자는 16px 이상으로 둔다. 16px보다 작으면 iOS가 확대한다.
- **대비**: 글자는 배경과 4.5:1 이상, 테두리·아이콘·포커스 링은 3:1 이상. 오류 색은 테마 `error`, 보조 글자는 `grey`를 쓴다.
- **키보드**: 클릭되는 것은 모두 `button`이나 링크로 만든다. 포커스 링은 `focusRing`을 `:focus-visible`에 단다. 모달은 열 때 첫 입력으로 포커스를 옮기고, 안에 포커스를 가두고, Esc로 닫고, 닫으면 연 요소로 포커스를 돌려준다.
- **IME**: 한글 조합 중 Enter(`isComposing` 또는 `keyCode 229`)는 제출 등 다른 동작으로 이어지지 않게 막는다.
- **이탈 경고**: 긴 답변처럼 다시 쓰기 어려운 입력은 저장하지 않은 변경이 있을 때 새로고침·탭 닫기(`beforeunload`)와 앱 안 이동에서 확인을 받는다. BrowserRouter라 `useBlocker`를 쓸 수 없어 `window.confirm`으로 묻는다. 제출에 성공한 뒤에는 묻지 않는다.
- **안내 위치**: 검증 결과와 처리 결과는 화면 안에 남긴다. 칸 오류, 폼 위 배너(`FormBanner`), 결과 화면(`ResultNotice`) 중 하나로 보여 주고, `alert`는 쓰지 않는다.
- **문구**: 오류는 무엇이 왜 잘못됐고 어떻게 고치는지 한 문장으로 쓴다(`답변은 1000자까지 쓸 수 있으니 줄여 주세요`). 사과 없이 사용자의 말로 쓰고, 서버 원문과 오류 코드는 우리 문구로 바꿔 보여 준다. 버튼 이름은 누르면 일어나는 일 그대로 쓴다(`다음: 지원 질문`, `가입 완료`). 마지막 단계와 중간 단계의 버튼 이름을 구분한다.

## 아직 맞추지 않은 공용 스타일

로그인·회원가입 밖의 화면에 영향이 있어 그대로 둔 것이다. 그 화면의 폼을 고칠 때 함께 정리한다.

- `src/styles/assets/Input.ts`의 `Input`(`TextInput`·`NumberInput` 포함)이 `:focus`에서 포커스 표시를 끈다. 공용 폼 부품을 쓰거나, 쓸 수 없으면 `:focus-visible`에 `focusRing`을 단다.
- `src/styles/assets/Div.ts`의 `Div` 기본값이 `white-space: nowrap`이다. 문구가 여러 줄이 될 수 있는 폼 영역에는 `white-space: normal; word-break: keep-all;`을 준다.
